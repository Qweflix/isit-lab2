# Лабораторная работа №2

## Проектирование информационной системы

### 1. Описание предметной области

Разрабатываемая система предназначена для автоматизации процессов регистрации, обработки и отслеживания обращений (заявок) пользователей в службу технической поддержки. 

**Проблема:** В отсутствии единой системы обращения поступают через разрозненные каналы (email, личные сообщения, звонки), из-за чего теряются заявки, отсутствует контроль за сроками выполнения (SLA) и нет прозрачности в работе сотрудников поддержки.

**Цель:** Создание централизованной информационной системы, обеспечивающей прозрачный цикл обработки каждого обращения от момента создания до закрытия с возможностью оценки качества работы.

---

### 2. Пользователи и роли

| Роль | Назначение | Основные задачи | Доступные функции | Уровень доступа |
| :--- | :--- | :--- | :--- | :--- |
| **Пользователь** | Подача обращений | Сообщать о неисправностях, отслеживать ход решения | Создание заявки, добавление комментариев, прикрепление файлов, оценка решения | Ограниченный (только свои заявки) |
| **Сотрудник поддержки** | Обработка обращений | Решать поступающие проблемы пользователей | Просмотр очереди, изменение статуса, назначение исполнителя, коммуникация | Служебный (заявки своей категории/отдела) |
| **Администратор** | Управление системой | Обеспечивать бесперебойную работу и аналитику | Управление пользователями и ролями, настройка категорий, просмотр отчетов | Полный (административный доступ) |

### 3. Сценарии использования

#### Сценарий 1: Создание новой заявки
* **Инициатор:** Пользователь.
* **Пошаговое описание:**
  1. Пользователь авторизуется в системе и переходит в раздел «Новая заявка».
  2. Заполняет поля: тема обращения, выбор категории проблемы, подробное описание.
  3. При необходимости прикрепляет скриншоты или файлы с ошибкой.
  4. Нажимает кнопку «Отправить».
  5. Система валидирует данные, регистрирует заявку с уникальным номером и присваивает статус «Новая».
* **Ожидаемый результат:** Заявка успешно сохранена в базе данных и отображается в личном кабинете пользователя.

#### Сценарий 2: Принятие заявки в работу
* **Инициатор:** Сотрудник поддержки.
* **Пошаговое описание:**
  1. Сотрудник открывает список нераспределенных заявок.
  2. Выбирает заявку из списка и просматривает её детали.
  3. Нажимает кнопку «Взять в работу».
  4. Система назначает сотрудника ответственным и меняет статус заявки на «В работе».
  5. Пользователю отправляется автоматическое уведомление.
* **Ожидаемый результат:** Заявка закреплена за специалистом, статус обновлен.

#### Сценарий 3: Добавление комментария и уточнение информации
* **Инициатор:** Пользователь / Сотрудник поддержки.
* **Пошаговое описание:**
  1. Участник открывает страницу конкретной заявки.
  2. Вводит текст уточнения в поле «Комментарий».
  3. Нажимает кнопку «Отправить».
  4. Система сохраняет комментарий в хронологической ленте заявки.
  5. Противоположная сторона получает уведомление о новом комментарии.
* **Ожидаемый результат:** Комментарий успешно отображен в истории диалога.

#### Сценарий 4: Закрытие заявки и оценка
* **Инициатор:** Сотрудник поддержки (решение), Пользователь (подтверждение).
* **Пошаговое описание:**
  1. Сотрудник поддержки решает проблему, оставляет финальный комментарий и переводит заявку в статус «Решена».
  2. Пользователь получает уведомление и проверяет результат.
  3. Пользователь выставляет оценку от 1 до 5 и нажимает «Подтвердить закрытие».
  4. Система переводит заявку в финальный статус «Закрыта».
* **Ожидаемый результат:** Заявка успешно завершена и архивирована.

#### Сценарий 5: Формирование аналитического отчета
* **Инициатор:** Администратор.
* **Пошаговое описание:**
  1. Администратор переходит в раздел «Аналитика и отчеты».
  2. Задает временной период и фильтр по категориям/сотрудникам.
  3. Нажимает кнопку «Сформировать отчет».
  4. Система агрегирует данные по количеству закрытых заявок, среднему времени решения и оценкам пользователей.
* **Ожидаемый результат:** Отчет отображен на экране с возможностью выгрузки.

### 5. Компоненты системы

| Компонент | Назначение | Взаимодействие |
| :--- | :--- | :--- |
| **Frontend (Веб-интерфейс)** | Пользовательский интерфейс (React / Vue) | Отправляет HTTP/HTTPS REST API запросы к Backend-серверу |
| **Backend (API Server)** | Бизнес-логика системы (Node.js / Python / Java) | Принимает запросы от Frontend, работает с БД и сервисом уведомлений |
| **Auth Service** | Сервис аутентификации и авторизации (JWT / OAuth2) | Проверяет права доступа пользователей и выдает токены |
| **Database (База данных)** | Реляционная БД (PostgreSQL) | Хранит данные пользователей, заявок, категорий и комментариев |
| **Notification Service** | Сервис отправки уведомлений (Email / Telegram) | Принимает команды от Backend и отправляет сообщения пользователям |

### 7. Концепция информационной системы

* **Назначение и цель:** Создание единой среды для управления технической поддержкой, ускорения обработки обращений и автоматизации контроля качества.
* **Основная функциональность:** Регистрация обращений, маршрутизация по категориям, отслеживание статусов, разграничение прав, аналитика работы специалистов.
* **Тип системы:** Трехуровневая веб-система (Frontend — Backend — Database).
* **Взаимодействие компонентов:** Клиентская часть передает пользовательские действия через асинхронные HTTP-запросы. Сервер проверяет права доступа через Auth Service, исполняет бизнес-логику, выполняет SQL-запросы к БД и инициирует отправку уведомлений.
